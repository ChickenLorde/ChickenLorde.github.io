Core Systems

Base-Building

Showcase of the base-building system in my indie game, Project Blue.

Blocks have pre-defined connectors on them that are given a local position and direction.
I then use dot products to calculate if two connectors on two blocks are facing each other and are close enough to connect.
If both criteria are met, the blocks will snap together.


Power Grid

Showcase of the power grid system in Project Blue.

Blocks are split into 3 categories: Consumers, Producers and Power Banks.
The power grid will take the total power generated by producers and distribute it evenly to every consumer that needs power. (Ex: If 10 total power is produces and there's 1 consumer, it will receive the full 10 energy / sec. 3 consumers will only receive 3.33 energy / sec each.)

If there are no consumers that need power, the power grid will then begin to charge power banks, using the same logic as consumers.
Consumers will use energy from power banks before using their own energy.


Crafting

Showcase of the crafting system in Project Blue.

Raw resources you collect in expeditions can be deposited into the resource reserve inside of your outpost.
You can then navigate to the crafting tab of your outpost and select a recipe to view various information, such as: Resources required, how many of those resources you have and how much of that recipe you currently have in storage.
When you craft a recipe, it goes directly into storage with blocks going into a special block storage.


Procedural World Generation

A seeded world generation system in my game.

The only thing generating right now is asteroid clusters. In the future I want to add biomes, different asteroid types, enemy outposts, planets, etc.
How it works is that when the player explores 50x50 unit areas called "chunks" it will load all of the data in that chunk.
Based on the seed and a deterministic math algorithm, it decides where asteroid clusters should spawn and where the asteroids in that cluster spawn. I also added a feature to add chunk overrides which allows any changes made to chunks to persist even when they reload, such as destroying or moving an asteroid.


Fleet Behavior

Fleets act like a hivemind in that a fleet gives individual ships commands to achieve goals for the entire fleet.

It uses a priority goal system that I created where the fleet can assign ships goals to accomplish, such as flying to a destination or attacking a target. The goals give the ships the steps required to accomplish it as well as a priority. Every frame, the ship will execute the goal with the highest priority, but can store up to 2 other goals as "memory."

One example of a fleet goal is V-formation which assigns the ships the goal of flying to a point relative to the leader to form a V-shape.


Ship Pathfinding

This is just an A* pathfinder that I implemented in my game. It allows ships to pick from 16 directions to move in and is much smarter than the navigation system but can't update on-the-fly. This is mainly used for general path planning while the navigation system actually follows the path generated.

Essentially, A* will explore "nodes" around it in 16 directions. It will then store those nodes in an open list which is basically "nodes that can be explored later". The algorithm will then calculate the cost of moving to each node. The cost is calculated by summing 3 values, the h-cost, the g-cost and the penalties. The H-cost is the estimated distance from the node to the goal, usually calculated by the straight line distance to the goal. The G-cost is the accumulated distance from node-tonode and the penalties are decided by me. The only penalty so far is for zigzagging by checking if the node points in a completely different direction from the previous node.

Ultimately, A* will repeat this process until it reaches the goal, finding the most optimal path.


Dynamic Navigation

Every frame, ships will cast rays in every direction around itself, each ray returns how far it traveled before it hit something and what direction it's facing.

The navigation system will then "score" each direction based on how close it points towards the destination. The score will be penalized the closer the direction would get to an object. Another penalty is for changing directions from the direction the ship is already moving in to discourage jagged flight patterns. Essentially, the ship will be pulled towards its destination while avoiding objects along the path.
